# КРИТИЧЕСКИ ВАЖНЫЕ ИНСТРУКЦИИ ПО БЕЗОПАСНОСТИ

## 🔴 НЕМЕДЛЕННО ВЫПОЛНИТЕ ЭТИ ШАГИ:

### 1. Отзовите текущий токен бота
Ваш токен бота был в открытом доступе в `.env` файле и возможно в git истории.

**Действия:**
1. Откройте @BotFather в Telegram
2. Выберите ваш бот
3. Выберите "API Token" → "Revoke current token"
4. Скопируйте новый токен

### 2. Удалите `.env` из git истории
```bash
# Удалите файл из истории git
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all

# Принудительно отправьте изменения (ВНИМАНИЕ: это переписывает историю)
git push origin --force --all
```

### 3. Настройте переменные окружения
Скопируйте `.env.example` в `.env` и заполните реальными значениями:

```bash
cp .env.example .env
```

Отредактируйте `.env`:
```env
# Telegram Bot Configuration
BOT_TOKEN=ваш_новый_токен_бота
ADMIN_ID=1093678594

# Database Configuration
DB_HOST=localhost
DB_PORT=5432
DB_USER=hookah_user
DB_PASSWORD=Solano2011!.-  # СМЕНИТЕ ЭТОТ ПАРОЛЬ!
DB_NAME=hookah_db
DB_SSLMODE=require  # Используйте require для продакшена

# Web Application
WEBAPP_URL=https://hookah-test.ru
WEBAPP_PORT=8080
```

### 4. Смените пароль базы данных
```bash
# Подключитесь к PostgreSQL
psql -U postgres

# Смените пароль
ALTER USER hookah_user WITH PASSWORD 'новый_безопасный_пароль';
\q
```

Обновите `DB_PASSWORD` в `.env` файле.

### 5. Примените миграции
```bash
# Запустите бота для применения новых миграций
go run cmd/bot/main.go
```

### Что нужно сделать в продакшене:

#### Безопасность БД:
- Включите SSL для PostgreSQL (`sslmode=require`)
- Используйте сертификаты для шифрования соединения
- Ограничьте доступ к БД по IP через pg_hba.conf

#### Rate Limiting:
- Текущая реализация использует in-memory map
- Для продакшена используйте Redis или другое решение
- Добавьте глобальный rate limiter на уровне nginx/API Gateway

#### HTTPS:
- Обязательно используйте HTTPS для веб-сервера
- Настройте Let's Encrypt сертификаты
- Перенаправляйте HTTP → HTTPS

#### Мониторинг:
- Добавьте структурированное логирование (zerolog/zap)
- Настройте alerts на подозрительную активность
- Логируйте попытки неавторизованного доступа

## 🔒 Рекомендации по безопасности на будущее:

1. **Никогда не коммитьте:**
   - Токены, API ключи
   - Пароли
   - Приватные ключи
   - `.env` файлы

2. **Используйте:**
   - Переменные окружения
   - Секреты менеджеры (Vault, AWS Secrets Manager)
   - `.env.example` для документирования требуемых переменных

3. **Регулярно:**
   - Ротируйте токены и пароли
   - Аудитируйте логи на утечки
   - Обновляйте зависимости
   - Проверяйте репозиторий на секреты (git-secrets, gitleaks)

4. **Pre-commit hook** для предотвращения коммита секретов:
   ```bash
   # .git/hooks/pre-commit
   #!/bin/bash
   if git diff --cached | grep -iE '(password|token|secret|key).*=.*[^example]'; then
       echo "⚠️  Возможна утечка секретов!"
       exit 1
   fi
   ```
